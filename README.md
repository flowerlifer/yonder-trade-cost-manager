# Yonder Trade Cost Manager

用于人民币贸易项目的成本与投资测算，支持多项目、费用增删改、分类选择、资金比例、独立利润比例、亏损分摊和 Excel 导出。Supabase 提供唯一管理员密码登录、RLS 隔离及云端保存。修改后需点击“保存项目”。

## 本地运行

安装 Node.js 20.9+（建议当前 LTS）和 npm：

```sh
npm ci
```

复制 `.env.example` 为 `.env.local`，填写：

```dotenv
NEXT_PUBLIC_SUPABASE_URL=你的项目URL
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=你的公开publishable_key
NEXT_PUBLIC_DEMO_MODE=false
```

不要填写 service_role、secret key 或密码。运行 `npm run dev` 后访问 http://localhost:3000，用已有管理员邮箱密码登录。未配置云端时不会自动加载演示数据。

数据库配置见 [SUPABASE_SETUP.md](SUPABASE_SETUP.md)。已完成迁移的数据库无需重复迁移；管理员 UID 只在数据库维护。

## 检查

```sh
npm run check
npm run lint
npm test
npm run build
```

`npm start` 启动生产构建。测试使用本地测试对象，不向远程数据库写入测试或演示数据。

## GitHub 与敏感数据

仅上传至 Private 仓库。`.env.local`、依赖、构建输出、备份及常见财务导出格式已被忽略。不要把密码、数据库连接串、令牌或真实账本放进源码或提交历史；忽略规则不能清除历史泄露，也不能替代提交内容审查。

## Vercel 部署（手动）

1. 在 Vercel 导入 GitHub 私有仓库，框架选择 Next.js。
2. 配置上面三个环境变量，演示模式保持 `false`，仅使用公开 publishable key。
3. 使用默认安装、构建与输出设置；确认后由你发起部署。
4. 在 Supabase Auth URL Configuration 中配置正式 Site URL 及需要的允许回调地址，保持公开注册关闭。
5. 部署后使用管理员账户验收保存、刷新及重新登录后的读取。

本次开发不会自动部署或修改远程数据库。客户端公开变量会包含在浏览器代码中，数据权限依赖数据库 RLS。

## 使用限制

每个项目独立保存，切换或刷新前请保存。当前为单人编辑模型，不含并发冲突合并。自定义分成合计须为 100% 才能形成有效分配；金额按十进制计算，显示到分可能存在尾差。

## 预计成本与实际投入
页面最前面新增七项预计成本，合计只读；每笔原费用可填写已投入金额。还需投入金额等于预计总成本减已投入合计；投足显示“已投足”，超出显示正数超支金额。货物清单支持名称、数量、单位、采购金额和备注，独立汇总。

预计成本和货物清单不改变原有成本、利润、资金比例、独立利润比例及亏损分摊公式，也不会重复计入成本。采购金额为该条总额，不自动按数量乘单价；已投入金额允许超过原费用金额，用于真实记录和显示超支。旧项目缺少字段时按零/空清单显示，不自动推断历史付款。

这些字段随“保存项目”写入现有 projects.data JSON，原事务函数完整保留此快照；无需数据库改表或新增迁移。Excel最前面为预计成本和投入汇总，其次为货物清单，成本表增加已投入金额。旧数据无需迁移，首次编辑保存后包含新字段。未执行远程SQL、未部署。

## 成本标签页与按预算出资
成本区域按“预计成本 → 成本统计 → 已投入成本”排列，与投资人管理处于同一导航区域，默认预计成本。货物清单在已投入成本中，投入、剩余及超支汇总始终显示在导航上方。

新项目按预计总成本和可编辑资金比例自动生成出资金额，比例合计必须100%才是有效分配。预算先以四舍五入取到分，前N-1位金额向下取到分，最后一位承担余额（包括最后一位比例为零的情况），确保总额精确一致且无负数。比例无效时金额仅供预览，禁止确认利润方案；仍允许保存草稿。预算修改实时更新出资，Excel使用同一金额。

历史项目未设置 fundingMode 时保留原手填金额，自动反算比例（末位补足100%）；用户点击确认转换后才按预计成本生成金额。原始出资金额来自手动输入，现在新项目及已确认转换项目来自预算比例计算。按资金模式的利润分配仍按实际生成金额占比计算，因此分位尾差可能造成极小比例变化；独立利润比例、总利润与亏损公式不变。新增资金比例、模式通过原JSON快照保存，无需迁移。未部署或执行远程SQL。

已投入成本中可新增独立投入记录，手动填写名称与金额，支持待投入/已投入双向切换及删除。只有已投入状态计入已投入汇总；待投入单独汇总，不改变原利润。不要将同一付款同时登记到费用的已投入金额。随项目JSON保存并导出Excel，旧项目默认空清单，无需迁移。

预计成本改为八项：采购成本、人工费、包装成本、运输成本、进口税、出口税、其他、进口费。原七项预算第六项改名为出口税，金额不变；进口费追加为零，避免旧数据错位。新项目成本统计默认八项；旧项目点击补齐八项费用即可添加缺少项，不覆盖原费用。已投入成本内先显示已采购货物，再显示待投入记录。

成本统计现为只读八类已投入汇总，来源为已投入记录与历史费用已投入金额；未分类或无法匹配分类归其他，待投入不计入。原利润仍使用历史费用总额。历史费用已投入金额移至已投入成本内编辑。预算数组索引不变，仅展示顺序将进口费放其他前。

采购成本显示为采购费用、进口费显示为进口清关费，旧分类记录仍正确归类；预计成本投足状态改为已投入。预计成本与成本统计底部新增饼图及各费用金额、百分比图例，零总额显示暂无数据。

已采购货物现改为已投入，第一栏为费用分类，金额计入实际投入。待投入仅列出待付款项，不提供状态选择，点击转为已投入移至上方。旧已付款记录自动整理到上方显示，保存后持久化，原名称仍保留；原货物金额现在按已投入统计，注意检查与历史费用付款是否重复。

当前界面已移除历史费用编辑区块，但历史已投入金额继续参与汇总，避免遗漏旧账。添加已投入与待投入按钮和分类框水平对齐。

总成本现在统一等于预计成本八项之和，单位成本、预计利润、利润率、保本价及Excel同步使用此来源。历史费用明细不再决定总成本；缺少预算的旧项目按零计算，请填写预计成本，旧记录本身不删除。
